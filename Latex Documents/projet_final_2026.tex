\section*{1. Introduction}

La modélisation mathématique consiste à représenter un problème réel à l'aide d'outils mathématiques afin de mieux le comprendre, l'analyser et proposer des solutions.

Dans le domaine de l'informatique, la modélisation intervient dans de nombreux contextes :

\begin{itemize}
\item réseaux sociaux ;
\item moteurs de recherche ;
\item cybersécurité ;
\item traitement d'images ;
\item intelligence artificielle ;
\item systèmes de recommandation ;
\item applications GPS ;
\item analyse de données ;
\item détection de fraude ;
\item systèmes d'aide à la décision.
\end{itemize}

Ce projet constitue une application des notions étudiées dans le cours de Mathématiques pour Informaticien.

\vspace{0.3cm}

\section*{2. Objectif du projet}

L'objectif du projet n'est pas de construire un modèle mathématique complexe ou de développer une application informatique complète.

L'objectif est de montrer votre capacité à :

\begin{itemize}
\item comprendre un problème informatique ;
\item identifier ses éléments essentiels ;
\item choisir des outils mathématiques appropriés ;
\item construire un modèle cohérent ;
\item expliquer comment ce modèle pourrait être utilisé pour résoudre le problème étudié.
\end{itemize}

La qualité du raisonnement sera davantage valorisée que la complexité mathématique.

\vspace{0.3cm}

\section*{3. Portée du projet}

Le projet doit rester adapté au niveau d'un étudiant de première année en informatique.

Vous n'êtes pas tenus de :

\begin{itemize}
\item développer un programme informatique ;
\item implémenter un algorithme dans un langage de programmation ;
\item utiliser des bibliothèques spécialisées ;
\item effectuer des simulations numériques avancées ;
\item construire un modèle de niveau recherche ;
\item utiliser des méthodes mathématiques non étudiées dans le cours.
\end{itemize}

Un modèle simple, cohérent et correctement justifié sera davantage valorisé qu'un modèle complexe mal maîtrisé.

\section*{5. Structure attendue du rapport}

Le rapport devra comporter les sections suivantes.

\subsection*{5.1 Présentation du problème}

Présenter le contexte du problème étudié.

Exemples :

\begin{itemize}
\item recommandation d'amis dans un réseau social ;
\item calcul d'itinéraire dans une application GPS ;
\item détection de spam ;
\item détection de fraude ;
\item analyse d'un réseau informatique ;
\item système de recommandation ;
\item traitement d'images.
\end{itemize}

\subsection*{5.2 Identification des éléments du problème}

Identifier clairement :

\begin{itemize}
\item les acteurs ;
\item les variables ;
\item les données ;
\item les contraintes ;
\item les objectifs.
\end{itemize}

\subsection*{5.3 Choix des outils mathématiques}

Expliquer quelles notions du cours sont utilisées.

Par exemple :

\begin{center}
\begin{tabular}{|l|l|}
\hline
Notion & Utilisation \\
\hline
Ensembles & Représentation des utilisateurs \\
Graphes & Relations entre utilisateurs \\
Matrices & Représentation des connexions \\
Probabilités & Estimation d'un risque \\
Statistiques & Analyse de données \\
Fonctions & Modèle de décision \\
\hline
\end{tabular}
\end{center}

\subsection*{5.4 Construction du modèle}

Construire une représentation mathématique du problème.

Le modèle peut utiliser :

\begin{itemize}
\item des ensembles ;
\item des relations ;
\item des fonctions ;
\item des probabilités ;
\item des statistiques ;
\item des matrices ;
\item des graphes ;
\item des systèmes linéaires ;
\item ou une combinaison de plusieurs de ces outils.
\end{itemize}

Toutes les hypothèses retenues devront être clairement justifiées.

\subsection*{5.5 Algorithme ou procédure d'étude}

Présenter une démarche permettant d'utiliser le modèle construit.

Cette démarche peut être présentée sous forme :

\begin{itemize}
\item d'algorithme ;
\item de pseudo-code ;
\item d'organigramme ;
\item ou d'une description détaillée des étapes.
\end{itemize}

L'utilisation d'un langage de programmation n'est pas requise.

L'objectif est de montrer comment le modèle pourrait être exploité pour résoudre le problème étudié.

\subsection*{5.6 Analyse et interprétation}

Expliquer :

\begin{itemize}
\item ce que le modèle permet d'obtenir ;
\item quelles informations il fournit ;
\item quelles décisions il permet de prendre ;
\item quels avantages il apporte dans le contexte étudié.
\end{itemize}

\subsection*{5.7 Limites du modèle}

Tout modèle constitue une simplification de la réalité.

Identifier :

\begin{itemize}
\item les hypothèses réalisées ;
\item les limites du modèle ;
\item les situations où le modèle pourrait être inadapté ;
\item les informations qui ne sont pas prises en compte.
\end{itemize}

\section*{6. Perspectives (facultatif)}

Cette section n'est pas obligatoire.

Elle permettra aux étudiants souhaitant aller plus loin de proposer :

\begin{itemize}
\item des améliorations du modèle ;
\item des extensions possibles ;
\item des liens avec l'intelligence artificielle ;
\item des liens avec la science des données ;
\item des approches plus avancées.
\end{itemize}

Aucune pénalité ne sera appliquée aux étudiants qui ne développent pas cette section.

\section*{8. Remarque importante}

La complexité du modèle ne constitue pas un critère d'évaluation.

Un modèle simple, cohérent, bien justifié et correctement expliqué obtiendra une meilleure note qu'un modèle complexe mal maîtrisé.

L'objectif principal du projet est de démontrer votre capacité à représenter un problème informatique à l'aide des outils mathématiques étudiés dans le cours.
